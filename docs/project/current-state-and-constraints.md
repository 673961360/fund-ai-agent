# 资金AI 3.0 当前现状与约束

## 1. 文档目的

本文档用于沉淀项目当前已确认事实、硬约束和未拍板事项。  
目标是避免在后续方案设计、AI 协作和开发实现中，把“目标态”“候选路线”“现状事实”混写。

---

## 2. 已确认事实

### 2.1 项目阶段
- 当前项目仍处于 2.0 阶段，3.0 是目标演进方向，不是已整体落地现状
- 当前整体完成度约 80%
- 项目已从“原型验证”转入“生产可用、稳定运行、合规可控”阶段

### 2.2 项目目标
项目目标已明确，包括但不限于：
- 节省人力投入
- 提升人均承载能力
- 增厚业务收益
- 保持已知场景风险事件 0 次

### 2.3 当前时间节奏
- 2026-04：整体测试准备
- 2026-05：少量对手试点，并同步探索 3.0 技术框架
- 2026-06：目标全面推广

### 2.4 生产化边界
- 独立 API 网关 + AI 能力隔离部署，是当前已定正式方向
- AI 开发代码和 Skill 对接生产机器猫数据与接口，必须走 API 网关
- 不允许绕过网关直连生产机器猫

### 2.5 前端边界
- 前端需要有“助手聊天”作为主要操作入口
- 前端面板与工作台主要承担辅助展示与状态承接
- 前端可通过 nginx 代理访问资金AI模块服务，但不是直连生产机器猫

### 2.6 组织边界
- 业务负责策略逻辑、规则表达、效果验证、业务能力沉淀
- IT / 平台负责数据治理、平台能力、运行安全、发布治理、生产托底
- AI 架构组负责网关等平台级架构统筹

---

## 3. 当前模块概况

当前核心模块包括：

- 缺口下达：接近完成，待接入机器猫接口
- 市场信息收集：已上线试用
- 市场情绪分析：数据不足，阶段性搁置
- 量价策略：接近完成，待真实接口联调
- 对手策略：接近完成，待真实接口联调
- 询价：当前不确定性最大，计划引入大模型
- 分户：后端接近完成，但生产化受接口联调和敏感数据边界约束
- 押券类型判断：后端逻辑已完成

---

## 4. 硬约束

### 4.1 数据合规
- L3 敏感数据不能直接给云端模型
- L3 场景不能简单理解为“完全不能上模型”
- 本地模型是正式候选路径

### 4.2 高风险能力治理
- 高风险执行类能力不能直接从办公环境放开
- 查询/分析/辅助决策类能力与执行类能力必须分区治理

### 4.3 可回退要求
- 所有 AI 能力必须可回退
- 自动化不能影响传统核心业务连续性

### 4.4 当前生产化卡点
当前真正制约生产化的关键问题主要有：
- L3 敏感数据合规边界
- 数据库与服务化底座不足
- 稳定运行 / 高可用 / 灾备能力不足
- 业务侧 vibe coding 成果难收敛为统一生产资产

---

## 5. 尚未拍板事项

以下内容属于讨论方向或候选路线，不能当成既定事实：

- “统一工作台”是否为最终产品形态，尚未拍板
- “助手聊天 + 默认盘 + AI 动态聚焦 + 异常提醒 + 待确认区”是交互设想，不是正式需求
- `FastAPI + LangGraph + Temporal` 是候选技术路线，不是正式技术决策
- `many tools + one orchestrator` 是候选思路，不是既定架构
- “业务写能力、平台写编排”是值得重点讨论的方向，但边界与协议尚未拍板
- orchestrator / tools / workflows / specialized agents 如何拆分，尚未定

---

## 6. 使用原则

后续所有方案、设计稿、AI 提示词和技术讨论，均应遵循以下原则：

1. 不把目标态写成现状
2. 不把候选技术写成既定技术
3. 不把交互设想写成正式需求
4. 不把“前端可调模块”误写成“前端可直连生产系统”
5. 不因 L3 合规问题直接排除本地模型路线
