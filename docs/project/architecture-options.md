# 资金AI 3.0 候选架构与技术路线

## 1. 文档目的

本文档用于讨论资金AI 3.0 的候选技术架构路线。  
本文档中的内容属于“推荐方案与论证方向”，不等于项目既定决策。

---

## 2. 候选总体架构

当前较值得重点论证的方向是：

前端工作台  
-> Assistant Gateway / 接入层  
-> 编排与决策层  
-> 领域能力层  
-> 执行与数据接入层  
-> API 网关  
-> 机器猫 / 数据接口 / 外部通道

该路线的核心思想是：

- 前端保持稳定
- 运行时可替换
- 会话理解与业务决策分层
- 自动化编排与长流程推进分层
- 执行能力与分析能力分区治理
- 所有链路可审计、可限流、可回退

---

## 3. 技术选型候选

### 3.1 FastAPI
适合作为领域能力服务层，承载：
- 缺口下达
- 市场信息收集
- 量价策略
- 对手推荐
- 押券类型判断
- 分户等明确输入输出能力

适用原则：
- 只是明确输入输出的能力接口，优先做成服务
- 业务侧更容易独立迭代与验证
- 便于平台层统一注册和治理

### 3.2 LangGraph
适合作为编排与决策候选层，承载：
- 会话理解
- 多步判断
- 路由分发
- 上下文驱动的流程切换
- 询价交互
- 资金缺口起始主流程中的多步判断与解释

适用原则：
- 需要模型参与多步推理和解释
- 需要根据上下文决定下一步路径
- 需要把多能力组织成可视化流程图或可维护编排图

### 3.3 Temporal
适合作为长流程与运行托底候选层，承载：
- 周期任务
- 长流程推进
- 人工确认等待
- 重试
- 补偿
- 失败恢复
- 异常升级
- 状态持久化

适用原则：
- 跨时间运行
- 需要等待与恢复
- 需要执行稳定性与流程托底
- 需要和人工确认节点结合

## 4. 建议的职责切分

### 4.1 模型负责什么
模型主要负责：
- 理解
- 判断
- 解释
- 路由建议
- 交互组织

### 4.2 编排层负责什么
编排层主要负责：
- 工具选择
- 任务拆分
- 状态流转
- 人工确认分流
- 异常升级
- 事件回流前端

### 4.3 服务层负责什么
服务层主要负责：
- 结构化输入输出
- 规则化处理
- 业务能力复用
- 独立服务化沉淀

### 4.4 执行层负责什么
执行层主要负责：
- 接口调用
- 状态更新
- 交易推进
- 执行结果回传
- 与机器猫 / 外部系统交互

---

## 5. 候选拆分建议

### 5.1 更适合作为 tools / services 的能力
- 市场信息收集
- 缺口下达
- 量价策略
- 对手推荐
- 押券类型判断
- 分户中的规则化部分

### 5.2 更需要 workflow 的能力
- 缺口下达到执行的长链路推进
- 询价过程跟踪
- 交易过程跟踪
- 人工确认后恢复执行
- 异常升级与回退

### 5.3 将来才值得升级为 specialized agent 的能力
- 询价交互
- 市场情绪分析
- 跨模块综合调度型能力

---

## 6. 当前不建议过早做的事

- 不建议一开始就做庞大的通用 Agent 平台
- 不建议把所有能力都包装成“智能体”
- 不建议在高风险执行环节过早放开模型直接决策
- 不建议前端直接依赖模型原始文本协议
- 不建议跳过 Tool 治理与审计协议，直接拼接脚本调用
