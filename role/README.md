# 角色说明

本目录定义了 fund-ai 项目中三个代理角色的职责边界与协作流程。

## 角色总览

| 编号 | 文件 | 角色 | 核心职责 |
|------|------|------|----------|
| 01 | `01-claude发布.md` | Claude 发布 | 方案收敛、任务拆解、发布任务包 |
| 03 | `03-codex计划.md` | Codex 计划 | 计划评估、风险识别、给出 ACCEPT/REVISE/REJECT 结论 |
| 04 | `04-codex执行.md` | Codex 执行 | 按计划执行代码变更，回写运行态文件 |

## 协作流程

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  01 Claude 发布  │────▶│  03 Codex 计划   │────▶│  04 Codex 执行   │
│  方案收敛/拆解   │     │  评估/评审       │     │  按计划执行      │
└─────────────────┘     └─────────────────┘     └─────────────────┘
        │                       │                       │
   创建任务包              ACCEPT/REVISE/REJECT       修改代码文件
   更新运行态文档           输出评审结论              回写 review-notes
```

## 各角色详细说明

### 01 — Claude 发布

**职责：**
- 读取 `current-task.md` 和对应真源，理解任务目标
- 收敛方案、定义任务边界、创建/更新运行态文档
- 发布任务时必须明确写出：任务目标、允许修改文件清单、禁止修改文件清单、完成判定标准

**允许操作：**
- 收敛方案、定义任务边界
- 创建/更新 `current-task.md` / `task-status.md` / `solution-proposal.md` / `decision-log.md` 及必要的里程碑或发布文档

**禁止操作：**
- 修改任何代码文件（`.py` / `.ts` / `.vue` / `.js` 等）
- 修改 `review-notes.md`

**完成后必须更新：**
- `current-task.md`
- `task-status.md`
- 必要时更新 `solution-proposal.md` / `decision-log.md`

---

### 03 — Codex 计划

**职责：**
- 读取 `current-task.md` 和对应真源，理解任务目标
- 校验任务是否符合当前项目状态：
  - 是否越过当前阶段边界（参考 stage deliverables / milestones）
  - 是否与当前里程碑进度一致
  - 是否引入真实集成（当前阶段禁止）
  - 是否修改禁止修改的文件
  - 任务依赖的前置条件是否已满足
- 输出：计划步骤、影响面、风险点
- 给出明确结论：**ACCEPT** / **REVISE** / **REJECT**

**拒绝与修订规则：**
- 当任务越过当前阶段边界、引入真实集成、修改禁止文件、缺少前置条件时，不得 ACCEPT
- 可缩范围修复的，给出 **REVISE**
- 明显冲突的，给出 **REJECT**
- **REJECT** 时必须列出具体冲突点和依据文件
- **REVISE** 时必须给出最小修订建议

**允许操作：**
- 仅输出计划与评估结论

**禁止操作：**
- 不做任何文件修改

---

### 04 — Codex 执行

**职责：**
- 按当前项目规则和当前任务流程继续
- 先读真源和当前任务包，严格按当前任务允许范围执行
- 完成后回写运行态文件

**执行前置条件：**
- 必须先检查最近一次 Codex 计划结论
- 仅当结论为 **ACCEPT** 时，才允许进入执行
- 若结论为 **REVISE** 或 **REJECT**，则禁止执行，必须先回到发布/计划环节修订任务

**允许操作：**
- 只修改当前任务允许修改的文件

**完成后必须更新：**
- `review-notes.md`
- `task-status.md`

## 使用方式

1. **启动新任务**：以「01 Claude 发布」角色启动会话，进行方案收敛与任务拆解
2. **评审任务包**：切换至「03 Codex 计划」角色，对任务包进行评审并给出结论
3. **执行任务**：仅在计划结论为 **ACCEPT** 后，以「04 Codex 执行」角色进入执行

角色切换时，需确保运行态文档（`current-task.md`、`task-status.md` 等）已正确回写，下一角色从最新真源读取状态。
